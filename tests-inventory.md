# Test inventory

Behaviours the old suite protected, kept on evidence: a `fix:` commit, a bug that shipped, a data-loss, security, update, signing or release path, or a contract other code depends on. Each entry says what must hold and why. The rewritten suites cover these from the source; the old tests are gone. 197 entries in all.

CI runs on every release target (linux-x64, linux-arm64, macos-x64, macos-arm64, windows-x64), so tests must be portable. Nothing may assume a POSIX shell, path separator or signal unless it's a per-platform branch that runs on that platform's CI.

Out of scope: `panels/dev.paperboard.actions` and `panels/dev.paperboard.ai` (deprecated).

Captured real-world data the new suites may use (kept, not tests): Game Server's Geyser/Floodgate and loader configs, SteamCMD `app_info_print` captures, the TF2 wiki map list, Steam Workshop API captures (`panels/dev.paperboard.gameserver/test/fixtures/`, `apps/panelapis/test/fixtures/`), and the Codex/Claude login transcripts and OpenCode integrations capture (`panels/dev.paperboard.agents/test/fixtures/`).

### Actions and events (daemon)

- **Action identity is bound to the token claim.** A panel-token socket that registers an action or emits a trigger/event under another panel's id is refused `FORBIDDEN` and nothing is broadcast. An `action_reply` from any socket other than the one the call went to is ignored. An `internal: true` action is refused `FORBIDDEN` to other panels and reaches only its own panel and the host. *Why:* `b481a4df` fix(daemon): bind action and trigger identity to the token claim. *Where:* `apps/paperboard/papercrane/actions.ts`, `apps/paperboard/papercrane/rpc/actions.ts`, `apps/paperboard/papercrane/ws.ts` [boundary: real WS server + real auth tokens]
- **Action names and projects are owned by the registering socket.** Another socket registering or unregistering a held `panelId/action` (or event-only name) gets `CONFLICT`. A batch with one conflict registers nothing. Names free up when the owner closes. `actions:project-define` groups `project/action` names, and removing the project or closing its socket removes its actions. Registering into an undefined or foreign project is refused. A socket gets `event` frames only for names it declared with `events:subscribe`. A new declaration replaces the old, `[]` unsubscribes, and `"*"` opts into all. *Why:* `d5eb8064`; contract (action projects used by Bot Creator and Game Server); contract (paperapi event transport); `fe4bb94c`. *Where:* `apps/paperboard/papercrane/actions.ts`, `apps/paperboard/papercrane/ws.ts` [boundary: real WS]
- **A service backing up its own panel from an action gets the backup as the answer.** The action resolves with the backup record instead of "Action service ... disconnected", and the restarted service answers the next call. `duringCall` naming a call sent to another connection is refused `FORBIDDEN`. *Why:* `61133145` fix(papercrane): an action that backs up its own panel is answered with the backup. *Where:* `apps/paperboard/papercrane/rpc/backups.ts`, `apps/paperboard/papercrane/actions.ts` [boundary: real compiled daemon + real panel service]

### Auth, tokens and pairing

- **Tokens persist and revocation is exact.** A panel token resolves to its `panelId` claim, a host token to none, an unknown token to null. Tokens and revocations survive a reload. Uninstalling a panel revokes only its tokens and drops the service token cache. Revocation takes effect on open sockets and on DAV Basic credentials minted from the token. When a host revokes itself, every panel and relay token it minted dies with it. `auth:revoke-self` replies only after the revocation is persisted. *Why:* security; `c068f335`, `7d777902`. *Where:* `apps/paperboard/papercrane/auth.ts`, `apps/paperboard/papercrane/panelServices.ts`, `apps/paperboard/papercrane/engine.ts`, `apps/paperboard/papercrane/dav.ts`
- **Panel credentials are minted by the host only, one per panel, never the master.** `issuePanelToken(id)` gives one stable `pcp_` token per panel and does not use up the pairing budget. `auth:panel-token` from a panel token is `FORBIDDEN`. A panel service gets `PAPERCRANE_PANEL_TOKEN` scoped to its panel and never `PAPERCRANE_TOKEN`. Reserved ids (`library`, `settings`, `landing`, `app-settings`, `default`, traversal, upper case) fail `isPanelId` and can't be issued a token. *Why:* security; `2e406919`, `a9dcf81a`, `2a0d5324`. *Where:* `apps/paperboard/papercrane/auth.ts`, `apps/paperboard/papercrane/panelServices.ts`, `packages/paperapi/src/panelIdentity.ts` [boundary: real child services]
- **Scoped and relay tokens can't escalate.** A token scoped to panel.a is refused reading panel.b's config directly and through a remote relay, can't rescope with `auth:scope` or upgrade with `auth:verify`, and gets 401 from `/dav/configs/...`, `/panel/<other>/...` and `POST /dav/session`. A relay-only token (`relayTo`) acts as the panel only over its tunnel, never appears in frames the remote receives, and is `FORBIDDEN` for local RPCs (`process:run`, `secrets:get`, `config:get`, `file:read`, `actions:register`); `remote:open` to another computer closes with `relay-scope`. *Why:* security; `ae27ec48`, `76fedbd4`, `413c4f71`. *Where:* `apps/paperboard/papercrane/ws.ts`, `apps/paperboard/papercrane/http.ts`, `apps/paperboard/papercrane/auth.ts` [boundary: real HTTP + pinned TLS remote daemon]
- **Pairing is opt-in, constant-time, and penalised per peer.** A fresh daemon answers `auth:pair` "not currently active" unless pairing was started. The 6-digit code (spaces allowed) yields a persisted `pc_` token. A wrong code locks that peer (5s, then 30s); one address's misses never block another's correct code, even with a spoofed `peerAddress`; IPv6 /64 and IPv4-mapped addresses share a penalty. A global miss budget ends the session and voids the code. *Why:* `0e168dd4`, `645acd05`, `872eb824`, `90dc00be`. *Where:* `apps/paperboard/papercrane/auth.ts`, `apps/paperboard/papercrane/ws.ts` [boundary: real WS with distinct local addresses]
- **WebSocket and HTTP authorities are allowlisted.** A DAV request or WS upgrade whose `Host` is a non-loopback name the daemon doesn't own gets 421 (with or without `--no-auth`). Allowed origins are loopback, `*.localhost`, `panel://` and `vscode-webview://`; lookalikes (`127.0.0.1.evil.com`, `localhost.evil.io`), `file://` and remote https are refused. The machine's own hostname and interface IPs over pinned TLS are still served. One non-loopback address holds at most 16 unauthenticated sockets (then 4429), and once the remote pre-auth budget is spent a loopback caller still connects. Invalid UTF-8 before auth closes only that socket, and the standalone daemon keeps serving. *Why:* `32db12ba` fix(papercrane): validate HTTP and upgrade authorities; security; `0c52625f`, `ae27ec48`. *Where:* `apps/paperboard/papercrane/http.ts`, `apps/paperboard/papercrane/ws.ts` (`isAllowedOrigin`), `apps/paperboard/papercrane/ws.ts`, `apps/paperboard/papercrane/main.ts` [boundary: real daemon on loopback ; real sockets from 127.0.0.2+, real daemon child process]
- **Credential and supervisor files are owner-only from creation.** `crane.json`, `authorized_tokens.json`, the vault and supervisor metadata are 0600 when first written. `local/` and `sockets/` are forced to 0700 even if an older build left 0755. Supervisor metadata writes env values named TOKEN/SECRET/KEY as `[redacted]`. *Why:* security; `f42d79e0`. *Where:* `apps/paperboard/papercrane/storage.ts`, `apps/paperboard/papercrane/engine.ts`, `apps/paperboard/papercrane/supervisor.ts`, `apps/paperboard/papercrane/paths.ts`

- **Sync is declarative and reports what it couldn't do.** A sync sets the global list and each guild's list in full (an emptied scope is set to empty), always with explicit integration types (guild-install only unless user-install is on); an unknown guild comes back as an error naming it while other scopes still sync; no application rejects instead of reporting success. *Why:* fail loudly / contract (Discord API). *Where:* `src/session.ts` (`syncSlashCommands`, `commandPayload`)
- **Command triggers stay bound.** A command's trigger id is `command:<scope>:<name>`, so deleting and recreating a command keeps its flows; an invocation resolves the guild-scoped command ahead of a global one, and the trigger exposes each parameter as a typed `values.<name>` field. *Why:* contract (flows reference trigger ids and fields). *Where:* `src/types.ts`, `src/session.ts` (`commandTriggerDefinition`)

### Interactions and messages

- **Interactions get exactly one first answer and stay answerable.** Respond then Follow Up reaches the same interaction and a repeated Respond edits the answer (reply, followUp, editReply); an unanswered slash command is auto-deferred and a racing Respond and auto-ack never both reply; a button click is acknowledged with deferUpdate and Respond sends a new message. *Why:* `a8732cac`, `6e84d4a8` fix(botcreator): Follow Up after Respond / edit on repeated Respond; Discord's 3 s window. *Where:* `src/discordOps.ts` (`InteractionOps`, `autoAcknowledge`), `src/session.ts`
- **Files are sent from web addresses only.** Send File accepts only an http(s) URL; a local path (e.g. `/home/me/.ssh/id_ed25519`) or `file://` URL is refused, so a flow can't upload host files to Discord. *Why:* security. *Where:* `src/discordOps.ts` (`fileFromUrl`)

### UI

- **Failures are shown, never guessed.** A failed health read shows the error instead of "offline" or a table of zeros, a failed invite link says so instead of "Generating…", and a refused bot delete shows the reason and keeps the bot and the confirm modal. *Why:* `3fe01b5c` fix(botcreator): show every failure. *Where:* `src/components/Commands.tsx`, `Overview.tsx`, `Invite.tsx`, `Configuration.tsx` [boundary: real panel components rendered in a browser against a failing service, `test/fixtures/failures.*`]

## terminal

### Sessions

- **Keystrokes never go to the wrong shell.** Resolving an unknown tab id throws "Unknown terminal tab" and an empty id throws "tab id required"; neither falls back to the last-active or first tab. *Why:* data integrity (input typed into the wrong shell). *Where:* `panels/dev.paperboard.terminal/src/service.ts` (`resolveTabIdPure`)
- **One-shot shell per platform.** One-shot commands run through `cmd.exe /d /s /c` on win32 and `sh -c` elsewhere. *Why:* contract (hardcoding `sh` breaks every Windows host). *Where:* `src/service.ts` (`resolveOneShotShell`)
- **Failures are shown.** A write into a session that couldn't be created rejects ("keystrokes were not sent") and the panel prints "Lost this terminal: <reason>"; `open-tab` rejects with the daemon's reason (e.g. conpty failing on Windows) instead of a blank terminal; a refused tab open or rename shows the reason. *Why:* `4246cb61` fix(terminal): show every failure; `7347933e` fix(terminal): show why a terminal could not open. *Where:* `src/service.ts`, `src/Terminal.tsx`, `src/App.tsx` [boundary: real App rendered in a browser against a failing service, `test/fixtures/failures.*`]

### Saved commands

- **The saved-commands file is never overwritten blindly.** An unreadable file, unknown version or malformed list is surfaced and Add is refused, so nothing is written over it; add and remove are queued and save before applying, and a failed save leaves the list unchanged. *Why:* data loss; `6ad67716` fix(terminal): serialize list changes. *Where:* `src/lib/savedCommands.ts` (`parseSavedCommandsDoc`)
- **Run outcome is only the exit the daemon reported, across restarts.** A run is "running" until the daemon reports its exit, success only for an observed exit 0, and a timed-out run is "timed-out" even if the killed child exits 0; accepted runs are recorded in the file (a record that can't be saved kills the child), and after a restart the service reclaims children the daemon still has and reports a vanished one as failed, never success. *Why:* `6ad67716` fix(terminal): own saved-command runs across restarts; contract (Home Pinned command widget). *Where:* `src/lib/savedCommands.ts`, `src/lib/runStatus.ts`, `src/service.ts` (SIGTERM handler)
